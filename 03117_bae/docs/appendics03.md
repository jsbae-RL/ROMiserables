# HTTP와 WebSocket의 차이점

## 1. HTTP란?
**HTTP(HyperText Transfer Protocol)**는 웹에서 데이터를 주고받기 위한 프로토콜입니다. 주로 클라이언트(브라우저)와 서버 간의 요청-응답(Request-Response) 방식으로 동작합니다.

### HTTP의 특징
- **비연결성(Connectionless)**: 클라이언트와 서버가 한 번 연결을 맺은 후, 클라이언트 요청에 대해 서버가 응답을 마치면 맺었던 연결을 끊어 버리는 성질.
- **무상태(Stateless)**: 각각의 요청은 독립적이며 이전 요청과의 관계를 유지하지 않음.
- **단방향 통신**: 클라이언트가 요청을 보내고, 서버가 응답을 반환하는 방식.
- **주로 REST API, 웹사이트, 파일 다운로드 등에 사용됨.**

## 2. WebSocket이란?
**WebSocket**은 실시간 양방향 통신을 가능하게 하는 프로토콜로, 클라이언트와 서버 간의 지속적인 연결을 유지할 수 있습니다.

### WebSocket의 특징
- **연결 지속(Connection Persistent)**: 한 번 연결되면 지속적인 통신이 가능.
- **양방향 통신(Bidirectional Communication)**: 클라이언트와 서버가 자유롭게 데이터를 주고받을 수 있음.
- **낮은 오버헤드**: HTTP의 요청/응답 방식보다 효율적이며, 데이터 전송 속도가 빠름.
- **주로 채팅, 게임, 실시간 알림 등에 사용됨.**

## 3. HTTP와 WebSocket의 차이점

| 구분 | HTTP | WebSocket |
|------|------|-----------|
| **연결 방식** | 요청-응답 후 연결 종료 | 한 번 연결하면 지속 유지 |
| **통신 방향** | 단방향 (클라이언트 → 서버) | 양방향 (클라이언트 ↔ 서버) |
| **프로토콜** | 요청(Request)과 응답(Response) 기반 | 지속적인 메시지 교환 가능 |
| **사용 예시** | 웹 페이지 로드, API 호출 | 채팅, 실시간 알림, 게임 |
| **오버헤드** | 요청마다 헤더 포함 (비효율적) | 초기 연결 후 오버헤드 감소 |

## 4. 언제 HTTP와 WebSocket을 사용해야 할까?
- **HTTP**: 단순한 데이터 요청(예: REST API, 웹 페이지 로드)이 필요할 때.
- **WebSocket**: 실시간 데이터 전송(예: 채팅, 금융 데이터 스트리밍, 멀티플레이어 게임)이 필요할 때.

## 5. 결론
HTTP는 일반적인 웹 페이지 로드 및 요청/응답 기반 서비스에 적합하고, WebSocket은 실시간 양방향 통신이 필요한 애플리케이션에 적합합니다. 상황에 따라 적절한 프로토콜을 선택해야 합니다.
